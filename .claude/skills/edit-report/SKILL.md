# 編修日報

這個站的形式：正文保留作者自己的想法，Claude 當技術編輯，在文章底部的留言區補充查證結果，被留言的句子畫上橘色波浪底線，和留言互相連結。所以技術問題預設是留言，不是改作者的句子。

對象是 `$ARGUMENTS` 指定的檔案。沒指定就用 `docs/reports/<今天日期>.md`；不存在的話，用 `docs/reports/` 底下最近修改的日報（`_template.md`、`index.md` 除外）。開始前跟作者說要編哪一篇，並把原稿備份到 scratchpad。

## 第一關：技術編輯

1. 用 Agent 工具呼叫 `tech-editor` 子代理，給它檔案路徑。
2. 把結果整理給作者，項目編號：照嚴重度列出每一項的原文、問題、留言文字和來源。不要自己加判斷，也不要省略來源。
3. 請作者決定每一項怎麼處理：
   - **留言**（預設）：正文不動。
   - **直接改**：用技術編輯的建議改法，或作者自己的改法，修改正文。
   - **不處理**。

   作者已經說過照預設處理，就不用停下來問。
4. 先套用「直接改」的項目，用最小幅度改原句。

## 第二關：文書編輯

用 Agent 工具呼叫 `copy-editor` 子代理，給它檔案路徑，並告訴它：
- 第一關直接改過的句子，意思不能動。
- 要留言的句子，就算說法不對，也不能替作者改正，意思要保留，它們之後會被畫底線。

把它的回報轉給作者。「用語替換」和「請作者決定」的項目要完整列出。

## 第三關：加留言

在修整後的正文上，對每個要留言的項目，從 1 開始依出現順序編號 N：

1. 正文裡要留言的那一小段原句，寫成 `<a class="claude-mark" id="ref-N" href="#comment-N">原句</a>`（技術編輯給的底線範圍，依修整後的文字調整）。不要跨段落，不要包到前後的標點。
2. 文章最後加一個 `## 留言` 小節，依編號放留言：

   ```md
   ## 留言

   ::: comment 1
   > 被留言的原句

   一到三句話說明正確的情況。[來源名稱](https://…)
   :::
   ```

   `> ` 那行引用畫底線的原句，讀者才知道在回哪一句；引用和留言內容之間要空一行，否則內容會被併進引用。留言會自動顯示 Claude 的頭像、名字和「回到原文」連結。

沒有要留言的項目就不加留言區。

較早的日報（例如 2026-10-19）用的是段落後的 `::: claude` 提醒框，那是舊格式，不要再用在新文章。

## 收尾

- 執行 `npm run docs:build`，確認構建成功。
- 跟作者說可以用 `npm run docs:dev` 在本機預覽。
- 不要自動 commit 或 push，等作者說。
- 作者要發布時，commit、push 到 `main`，Cloudflare 會自動部署。側邊欄、日報列表、日期副標和分類都是依檔名、frontmatter 和 `# 主題` 自動產生的，不用手動加。
