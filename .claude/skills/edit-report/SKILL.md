# 編修日報

這個站的形式：正文保留作者自己的想法，Claude 當技術編輯，用橘色提醒框補充查證結果。所以技術問題預設是加提醒框，不是改作者的句子。

對象是 `$ARGUMENTS` 指定的檔案。沒指定就用 `docs/reports/<今天日期>.md`；不存在的話，用 `docs/reports/` 底下最近修改的日報（`_template.md`、`index.md` 除外）。開始前跟作者說要編哪一篇，並把原稿備份到 scratchpad。

## 第一關：技術編輯

1. 用 Agent 工具呼叫 `tech-editor` 子代理，給它檔案路徑。
2. 把結果整理給作者，項目編號：照嚴重度列出每一項的原文、問題、提醒框文字和來源。不要自己加判斷，也不要省略來源。
3. 停下來，請作者決定每一項怎麼處理：
   - **加提醒框**（預設）：正文不動。
   - **直接改**：用技術編輯的建議改法，或作者自己的改法，修改正文。
   - **不處理**。
4. 先套用「直接改」的項目，用最小幅度改原句。

## 第二關：文書編輯

用 Agent 工具呼叫 `copy-editor` 子代理，給它檔案路徑，並告訴它：
- 第一關直接改過的句子，意思不能動。
- 要加提醒框的句子，就算說法不對，也不能替作者改正，意思要保留，它們之後會被畫底線。

把它的回報轉給作者。「用語替換」和「請作者決定」的項目要完整列出。

## 第三關：加提醒框

在修整後的正文上，對每個「加提醒框」的項目：

1. 用 `<span class="claude-mark">…</span>` 包住要提醒的那一小段原句（技術編輯給的底線範圍，依修整後的文字調整）。不要跨段落，也不要包到標點以外的多餘文字。
2. 在那一段後面空一行，加上提醒框：

   ```md
   ::: claude
   一到三句話說明正確的情況。[來源名稱](https://…)
   :::
   ```

   標題預設是「Claude 溫馨提醒」，要換標題就寫 `::: claude 自訂標題`。同一段有兩項時合併成一個框。

## 收尾

- 執行 `npm run docs:build`，確認構建成功。
- 跟作者說可以用 `npm run docs:dev` 在本機預覽。
- 不要自動 commit 或 push，等作者說。
- 作者要發布時：如果是新的一篇，同時在 `docs/.vitepress/config.mts` 的 sidebar 和 `docs/reports/index.md` 的列表加上這篇。然後 commit、push 到 `main`，Cloudflare 會自動部署。
