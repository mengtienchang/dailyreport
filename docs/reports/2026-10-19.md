# 日報站開張：為什麼選 GitHub、Cloudflare 和 VitePress

事實上，我想要寫日報已經很久了。這個 domain 我也買了將近一年了，甚至<span class="claude-mark">我也買了 WordPress</span>，但是一直都沒有堅持下來。我覺得我憋出一篇文章的成本還是太高，或許可以說是因為要求太高，但總之結果就是最後什麼都沒有。

::: claude
WordPress 本身是免費的開源軟體，下載就能用。要付費的通常是 WordPress.com 的方案，或是自己架 WordPress 用的主機。[WordPress.org](https://wordpress.org/about/)
:::

所以我秉持著能堅持一天算一天的原則，再次開啟了這個日報的計劃，希望這次可以撐久一點。隨便寫點什麼新知以及我的思考，看的人一天也不會有太大負擔，很快就能看完；我寫的也沒什麼負擔，能堅持得更久一點。

今天就簡單介紹這個站是怎麼建立起來的。如果有人看到我這些日報有了一些興趣，也想要建立自己的日報或是自己的網站，可以參考這篇，簡單地建立起來。

不過不得不說的是，現在的 AI 還是太強大了，一般不會什麼、需要學習什麼，我的反應就是問 AI。所以我講一點關於我的思考，一些技術上的操作可以去問 AI，會更快更方便一點。

我這個站是在 GitHub 上建立了一個公開的 repo，然後<span class="claude-mark">用 Cloudflare 的 Pages 部署功能做的</span>，框架是 VitePress。這個選擇思路是有一些故事的。

::: claude
這個站實際上是用 Cloudflare Workers 部署的，不是 Cloudflare Pages。兩者是不同的產品，後台都放在「Workers & Pages」底下，很容易搞混。想照著做的話選 Workers 就對了，Cloudflare 從 2025 年起也建議新專案直接用 Workers。[Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/)、[Cloudflare 部落格](https://blog.cloudflare.com/full-stack-development-on-cloudflare-workers/)
:::

首先是為什麼要選擇 GitHub，而不是我自己上傳部署檔案呢？因為我比較熟悉 GitHub 的版控歷程。而且因為是日報，我會想要讓他天天更新，但是如果要讓我每天重新上傳新的部署檔案，對我來說顯然是比較麻煩的。這裡就是第一段說的，這樣我堅持下來的成本就高了。所以我會需要一個能讓他自動更新的東西。<span class="claude-mark">所以我就直接在 GitHub 上做了</span>。

::: claude
放上 GitHub 本身不會讓網站自動更新，GitHub 在這裡負責存放內容。自動更新是 Cloudflare 做的：它連到這個 repo，每次 push 到 `main` 就自動構建並部署。[Workers Builds](https://developers.cloudflare.com/workers/ci-cd/builds/)
:::

然後我選的是用 Cloudflare 的 Pages 部署，而不是直接用 GitHub 的 Pages 部署，這點算是我個人的一點小心思。因為這個網域是我在 Cloudflare 上買的，<span class="claude-mark">我想要直接使用我的網域，所以我就在 Cloudflare 上搞定</span>。

::: claude
GitHub Pages 其實也能用自己的網域，在 DNS 加幾筆記錄就行。選 Cloudflare 省事的地方在於：網域在 Cloudflare 買的，DNS 本來就在 Cloudflare，綁定網域時會自動設好記錄。另外，這裡的「Cloudflare 的 Pages」跟上面一樣，實際上是 Workers。[GitHub Pages 自訂網域](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/about-custom-domains-and-github-pages)
:::

至於為什麼是 VitePress，這個我倒是覺得比較關鍵一點，這牽涉到想要做的網站是什麼類型。不得不承認，現在 AI 透過一句話就可以做出一個算是蠻有品質的網站介面，但是那對我來說有點太複雜了。我會開始糾結一些其他跟日報不相關的東西，比如說什麼顏色、版面什麼的，這些其實對於我的日報來說沒什麼幫助。<span class="claude-mark">所以我沒有選擇用什麼 React 或是 Vue 做一個網站介面</span>。

::: claude
VitePress 本身就是用 Vue 做的，每個 Markdown 頁面都會編譯成 Vue 元件，所以下一段才能在裡面寫 Vue。這裡指的是沒有自己用 React 或 Vue 從頭刻一個介面。[What is VitePress](https://vitepress.dev/guide/what-is-vitepress)
:::

在文件管理的開源框架上其實也依然有很多選擇，比如說我之前有用過的 MkDocs，主要是用 Python 語言的，這裡就出現一個 Python 目前比較不算這麼強勢的領域問題，<span class="claude-mark">前端畫面的渲染上 Python 確實不如 React 跟 Vue</span>。之前我嘗試用 MkDocs，但是我發現排版上有一些缺陷我無法忍受，改成 VitePress 就沒問題了。加上我甚至可以寫 Vue 檔案來豐富這個文件站的能力，所以我就直接選擇這個了。

::: claude
MkDocs 只在構建時用 Python 把 Markdown 轉成靜態網頁。瀏覽器看到的畫面由主題決定，主題是用 HTML、CSS、JavaScript 寫的，Python 並不負責前端渲染，所以排版的差別主要來自主題，不是語言。[MkDocs 主題開發](https://www.mkdocs.org/dev-guide/themes/)
:::
