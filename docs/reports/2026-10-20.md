# 要不要以日期錨定一天一篇

事實上，版面邏輯以及任務的完成範圍也是很值得說的事情，這跟日報能不能堅持下去有很大的關係。

正如前面說到的，如果一篇文章的完成成本太高，哪怕我興致很高，也很難堅持下來，因為對我來說太難了。作為一個比較懶、又比較三分鐘熱度的人，我需要知道完成這件事的成本不算太高，才能在哪怕非常艱難的狀態下也堅持下去。因為我知道完成這件事就是順手的事情，不需要消耗太大的心力，而堅持下來又會有比較可觀的結果，所以哪怕狀態比較不好，我也能堅持下去。

所以我需要知道一篇日報應該寫什麼、寫到什麼程度算結束，必須劃定一個明確的範圍作為終止線，不能無止盡地往下寫。同樣地，要保證狀態很差的時候也能寫下去，我就需要盡可能把這件事從申論題變成問答題，甚至是填充題。

我簡單地做了一個分類，分成三類：「為什麼」、「是什麼」、「怎麼做」。第一篇就是「為什麼」，因為對我來說 GitHub 跟 Cloudflare 部署比較容易，當然我本身也問了 AI 怎麼做，所以主要說明的是為什麼我要這樣做。「是什麼」比較類似知識點的分享，通常是我沒學過的東西，因為學過的我會預設很簡單，就會變成只寫為什麼要這樣做。最後是「怎麼做」，這個我暫時沒想到。不過反正我是按照 5W1H 思考的，哈哈，就是這麼樸實無華。

另外一個有趣的是，我做了兩個 agent。一個是技術編輯，主要負責檢查我說的知識起碼不是純亂講，做一個知識正確性的審查。<a class="claude-mark" id="ref-1" href="#comment-1">前面第一篇的留言就是他做的</a>。另一個是文書編輯，主要負責幫我潤飾表達上的一些語病或問題。簡單來說，這些都是為了讓我後續能更簡單、更低成本地完成這件事，讓我堅持更久、有更多的產出。
